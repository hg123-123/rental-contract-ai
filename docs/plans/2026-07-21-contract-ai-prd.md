# PRD：合同审查AI助手

## 问题陈述

大学生外出求职面临两类合同——**租房合同**和**劳动合同**，绝大多数人对合同条款中的门道一无所知。

当前的解决方案都有致命缺陷：
- **小红书/抖音搜避坑帖**：信息碎片化、不针对具体合同、无法验证可靠性
- **问父母/学长学姐**：不一定懂、不好意思频繁问
- **百度/知乎查法条**：法律术语看不懂、不知道哪条适用于自己的情况
- **ChatGPT/Claude 通用问答**：没有法律知识支撑、容易编造法条、无结构化分析

用户需要的是一个**懂法律、说实话、免费好用**的合同分析工具。

## 解决方案

一个 AI 驱动的合同辅助阅读助手，基于 RAG（检索增强生成）架构，让 AI 在分析合同时能实时检索真实的法律条文和风险经验库，而非依赖模型自身可能出错的训练记忆。

MVP 覆盖两类合同：
- **租房合同**：识别押金过高、维修责任推卸、违约金不对等、退租条件苛刻等常见陷阱
- **劳动合同**：识别试用期过长、薪资结构拆分、社保公积金缴纳、竞业限制、霸王条款等问题

定位为"合同知识科普 + AI 辅助阅读"，明确声明"不构成法律建议"。

## 用户故事

1. 作为准毕业生，我想要上传一份租房合同让 AI 帮我逐条分析风险，以便知道哪些条款对我不利、怎么跟房东谈
2. 作为应届生，我想要上传一份劳动合同让 AI 指出陷阱条款，以便在签约前保护自己的权益
3. 作为在校生，我想要直接问"押金不退怎么办"，以便快速获得基于真实法条的回答
4. 作为用户，我想要在分析完合同后继续追问细节，以便深入理解某一条款
5. 作为用户，我想要看到 AI 引用的法条原文而非编造的内容，以便信任分析结果
6. 作为用户，我想要用手机随时打开即用，以便在签合同现场快速查阅
7. 作为运营者，我想要把链接发到小红书/朋友圈获取第一批用户，以便验证产品价值
8. 作为运营者，我想要逐步积累风险知识库，以便让分析越来越准

## 实现决策

### 平台：Dify 聊天助手作为 MVP 交付形态

经过微信小程序（审核门槛高）、Vercel（国内被墙）、GitHub Pages（推送不稳定）、自建 Chatflow（多轮对话有 bug）等多轮技术尝试，最终确定使用 Dify 自带的聊天助手作为 MVP——零额外开发、原生多轮记忆、即刻可用。

### RAG 架构：三个知识库

- **法律知识库**（6 份文档）：以《民法典》租赁合同章节 + 住建部规章 + 杭州地方条例为主，按法条分块（500 字/块），同义词扩展确保口语查询能命中法律术语
- **风险知识库**（8 份文档）：30+ 风险点，人工录入的真实租房陷阱经验，自然语言灵活迭代
- **劳动法知识库**（8 份文档）：劳动合同法核心条款 + 社保公积金 + 加班费计算 + 杭州人才政策

### 模型选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 生成模型 | DeepSeek-V4-Pro | 中文法律文本理解优秀，价格低 |
| Embedding | 通义千问 text-embedding-v3 | 中文检索质量高，免费额度够 MVP |
| RAG 平台 | Dify 知识库 | 开箱即用，支持混合检索 |

### 系统提示词设计

- 角色定位：租房合同/劳动合同辅助阅读助手，帮助大学生看懂合同
- 硬性约束：可以解释条款、指出风险、引用法条、给谈判方向；禁止出具合规判断、禁止给具体修改措辞、禁止声称法律建议
- 禁用词：违法、违规、不合法、霸王条款、陷阱
- 引用规范：法条原文必须来自知识库，禁止编造

### 网络穿透：Cloudflare Tunnel

笔记本 Docker 运行 Dify，通过 Cloudflare Tunnel（免费）将 localhost 暴露至公网。Tunnel 重启后链接域名会变——MVP 可接受，成熟后迁移云服务器。

### 前端（保留但未用于 MVP 分发）

基于 React + Vite + TailwindCSS 构建了一个对话式 H5 页面，支持文件上传、合同文本分析（左右对照面板）、多轮追问、历史记录、分享等功能。因网络和部署稳定性问题，暂作为后续迭代的备用方案。

## 测试决策

### 测试策略

MVP 阶段不做单元测试。通过以下方式验证：

- **知识库检索质量**：用真实场景 query（如"押金退不退""空调坏了谁修""试用期最长多久"）逐一验证检索命中率
- **E2E 场景测试**：实际粘贴合同全文，检查 AI 是否识别了所有预埋的风险点
- **用户反馈**：分享链接给朋友试用，观察是否有回头使用和自发传播

### 后续测试

当迁移至云服务器后，对前端代码中以下模块编写单元测试：
- `desensitize.js`：数据脱敏函数（输入人名/身份证号等 → 验证输出为占位符）
- `storage.js`：localStorage 存取逻辑
- `api.js` 中的 `parseWorkflowOutput`：工作流输出解析

## 超出范围

- 微信小程序版本（审核门槛、个人资质限制）
- 独立品牌域名和落地页
- 支付和商业化功能（先验证价值再谈钱）
- 法律合规审核（定位为科普+辅助阅读，非法律服务）
- 用户账号体系和数据上云（MVP 用户直接打开链接使用）

## 进一步说明

### MVP 使用前提

产品可用需要三个条件同时成立：
1. 笔记本开机
2. Dify Docker 运行
3. Cloudflare Tunnel 运行

任意一个条件不满足，链接将失效。

### 升级触发条件

| 触发条件 | 升级动作 |
|---|---|
| 日活用户超过 10 人或 Tunnel 频繁断连 | 购买云服务器（¥68-200/月）部署 Dify |
| 用户反馈有价值后 | 开发独立品牌落地页 |
| 非杭州用户需求增多 | 扩展其他城市的知识库 |
| 量上来后成本需要优化 | 拆分轻量任务用免费模型，核心分析保留 DeepSeek-V4-Pro |

### 风险

- **笔记本不可靠**：MVP 可接受，告知使用时段或迁移云服务器
- **法律合规**：严格按"科普+辅助阅读"定位，每次回答末尾自动附加免责声明
- **知识库质量**：风险知识库依赖人工录入，需持续维护
- **模型幻觉**：RAG + 法条引用规范 + Embedding 同义词扩展三层防护
